2. ขั้นตอนนำเข้ามาใช้ (ที่ทำจริง)

  1. สมัครด้วยบัญชี GitHub ทำแล้ว

    เข้า app.aikido.dev แล้วเลือก Sign in with GitHub ไม่ต้องใช้บัตรเครดิต workspace จะชื่อตาม GitHub account (nathaphat-s)

  2. ติดตั้ง Aikido GitHub App และเลือก repo ทำแล้ว

    ระหว่างสมัคร GitHub จะถามว่าจะให้ Aikido เข้าถึง repo ไหน เลือกเฉพาะ cicd-checkmarx-poc (เพิ่ม/ลบภายหลังได้ที่ Manage Repos) App นี้ต้องมีสิทธิ์อ่านโค้ดและเขียน Checks / Pull requests เพื่อส่งผลกลับเข้า PR

  3. Aikido สแกน main ให้ครั้งแรกทันที ทำแล้ว

    หน้า Repositories แสดงจำนวน issue บน branch หลัก แยกตามความรุนแรง (Critical · High · Medium · Low) และจำนวนที่ Aikido กรองทิ้งเอง (Ignored)

  4. ดูภาพรวมใน Dashboard ทำแล้ว

  5. ลองใช้ local scanner ใน GitHub Actions ต้องใช้แผนเสียเงิน

    เตรียม job aikido ใน .github/workflows/ci.yml (branch feat/aikido-ghas) ไว้แล้ว ใช้ image aikidosecurity/local-scanner รัน scan (SAST + dependency + IaC + secrets) และ image-scan แบบ PR gating ที่ --fail-on high แล้วส่งผลเข้า report.html แต่ token ของ local scanner มีให้เฉพาะแผนเสียเงิน job นี้จึงข้ามพร้อม warning เมื่อไม่มี AIKIDO_API_KEY

    docker run --rm -v "$PWD":/src -w /src -e AIKIDO_API_KEY --entrypoint aikido-local-scanner \
  aikidosecurity/local-scanner:latest scan /src \
  --repositoryname cicd-checkmarx-poc --branchname "$BRANCH" \
  --gating-mode pr --base-commit-id "$BASE" --head-commit-id "$GITHUB_SHA" \
  --fail-on high --gating-result-output /src/reports/aikido-code.json

  6. เปิด PR เดโม #7 และ #8 ทำแล้ว

    สร้าง branch ใหม่จาก main ล่าสุด แล้วใส่โค้ดฟีเจอร์เดียวกับ Snyk demo เป็น commit เดียว เพื่อให้ Aikido สแกนโค้ดชุดเดียวกับที่ Snyk สแกน

    PRBranchเทียบกับความคาดหวัง
    #7demo/aikido-vulnerableSnyk #4ควร fail
    #8demo/aikido-secureSnyk #5ควรผ่าน

  7. เปิด PR checks ใน Aikido แล้วสั่งสแกนใหม่ ทำแล้ว

    ตอนเปิด PR ครั้งแรกมีแค่ security/snyk เพราะ Aikido ยังไม่ได้เปิด PR checks ให้ repo นี้ หลังเปิดใน dashboard (แท็บ Checks / Pull Requests) แล้ว push commit ว่าง 1 ครั้งเพื่อ trigger check ของ Aikido ก็ขึ้นภายในประมาณ 50 วินาที

3. ผลแสดงบน PR อย่างไร

Aikido ไม่ได้อยู่ใน GitHub Actions workflow ของเรา App สแกนบนเซิร์ฟเวอร์ของ Aikido แล้วส่งผลกลับมา 3 ทาง:

① Check ในกล่อง Checks ของ PR

7. AutoFix ทำงานอย่างไร

ทำงานกับอะไรผลที่ได้

PR check (เช่น #7)โค้ดที่ PR นั้นเพิ่มเข้ามาcomment + Suggested change ให้ developer กด Commit suggestion เองใน PR นั้น ไม่เปิด PR แยก
AutoFix ที่เห็นตอนนี้มาจาก Pro trial หลัง trial หมดอาจใช้ไม่ได้ (หน้า pricing ของ Aikido เขียนขัดกันเองว่าแผนฟรีมี AutoFix หรือไม่) ตอนสรุป POC ควรนับเป็นฟีเจอร์ของแผนเสียเงิน

8. ข้อจำกัดที่เจอ และสิ่งที่ควรทำต่อ

ข้อดี
  • ติดตั้งเร็วมาก ไม่ต้องแก้ CI ไม่ใช้ CI minutes
  • จับช่องโหว่ในโค้ดได้มากกว่า Snyk ในเดโมนี้ (8 vs 5) รวมถึง SQLi
  • comment อยู่บนบรรทัดโค้ด อ่านง่าย มี suggested change
  • รายงานเฉพาะ "ปัญหาใหม่" ของ PR ไม่โดนบล็อกเพราะหนี้เก่าใน main
  • PR secure ผ่าน ไม่มี false positive ระดับสูง
ข้อจำกัด
  • Local scanner / gating ใน CI ต้องใช้แผนเสียเงิน ผลจึงไม่เข้า report.html
  • เกณฑ์ค่าเริ่มต้น fail เฉพาะ Critical (Snyk/CodeQL ใช้ High)
  • พลาด command injection, TLS off, hardcoded password
  • PR check ไม่สแกน k8s และ container image
  • Deep Review / AutoTriage ใช้เครดิต แผนฟรีไม่มี

สิ่งที่แนะนำให้ทำต่อ

  1. เปลี่ยนเกณฑ์ PR check ใน Aikido จาก Critical เป็น High ให้เทียบกับ Snyk/CodeQL ได้ยุติธรรม แล้ว push commit ว่างเข้า #7 อีกครั้ง
  2. ลองกด Commit suggestion ของ SQLi บน branch สำเนาของ #7 แล้วรัน npm test ดูว่า fix ใช้ได้จริงไหม
  3. ลอง AutoFix 1 issue บน main ระหว่างยังอยู่ใน trial แล้วรีวิว PR ที่ได้
  4. ถ้าเลือก Aikido จริง: ทำให้ Aikido Security: check code เป็น required check ใน branch protection
