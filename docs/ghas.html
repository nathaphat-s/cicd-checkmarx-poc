1. GHAS มีอะไรบ้าง

ส่วนทำอะไรเปิดที่ไหนสถานะใน repo นี้
CodeQL (code scanning)SAST: วิเคราะห์ data flow จาก input ไปถึงจุดอันตรายworkflow (job ghas)ใช้งาน
Dependency ReviewSCA บน PR: บอก dependency ที่ PR เพิ่มเข้ามาและมี CVEworkflow (job ghas)ใช้งาน หลังเปิด Dependency graph
Dependabot alerts / security updatesแจ้ง CVE ใน dependency บน main และเปิด PR อัปเกรดให้Settings → Code securityยังปิด
Dependabot version updatesเปิด PR อัปเดต dependency ทุกสัปดาห์.github/dependabot.ymlทำงานหลัง merge เข้า main
Secret scanning + push protectionหา token ใน repo และบล็อก push ที่มี tokenSettings → Code securityเปิดอยู่แล้ว
IaC / Container image——ไม่มีใน GHAS

2. ขั้นตอนนำเข้ามาใช้ (ที่ทำจริง)

  1. เช็กว่า repo เป็น public ทำแล้ว

    gh repo view --json visibility → PUBLIC จึงใช้ GHAS ได้ฟรีโดยไม่ต้องมี license

  2. เช็ก setting ของ Code security ทำแล้ว

    secret scanning และ push protection เปิดอยู่แล้ว ส่วน Dependabot alerts / security updates ยังปิด และ Dependency graph ตอนแรกก็ปิด ทำให้ Dependency Review รันไม่ได้รอบแรก (Dependency review is not supported on this repository) พอเปิดแล้วก็ใช้ได้

  3. เพิ่ม job ghas ใน .github/workflows/ci.yml ทำแล้ว

    อยู่ใน branch feat/aikido-ghas ใช้ action ทางการของ GitHub ไม่ต้องใช้ token เพิ่ม

    ghas:
  name: GHAS (CodeQL + Dependency Review)
  permissions: { contents: read, security-events: write, actions: read }
  steps:
    - uses: actions/checkout@v4
      with: { fetch-depth: 0 }
    - uses: github/codeql-action/init@v3
      with: { languages: javascript-typescript, queries: security-extended }
    - uses: github/codeql-action/analyze@v3      # อัปโหลดผลขึ้น Security tab ด้วย
      with: { output: codeql-results }
    - run: node scripts/gate-count.mjs codeql reports/ghas-codeql.sarif   # fail ถ้า High ขึ้นไป
    - uses: actions/dependency-review-action@v4
      with: { base-ref: <merge-base กับ main>, head-ref: ${{ github.sha }}, fail-on-severity: high }

    CodeQL รายงานผลแต่ไม่ fail เอง จึงเขียน scripts/gate-count.mjs นับ alert ที่ security-severity ≥ 7.0 (เกณฑ์เดียวกับที่ GitHub แสดงเป็น High) ให้ใช้เกณฑ์เดียวกับ Snyk และ Aikido

  4. เพิ่ม .github/dependabot.yml ทำแล้ว

    อัปเดต npm (รวม minor/patch เป็น PR เดียว), Docker base image และ GitHub Actions ทุกสัปดาห์

  5. เปิด PR เดโม #9 และ #10 ทำแล้ว

    base เป็น feat/aikido-ghas (branch ที่มี job GHAS) diff ของ PR จึงเห็นแค่โค้ดฟีเจอร์ เหมือน #4/#5 ทุกไฟล์

    PRBranchเทียบกับความคาดหวัง
    #9demo/ghas-vulnerableSnyk #4 · Aikido #7ควร fail
    #10demo/ghas-secureSnyk #5 · Aikido #8ควรผ่าน

  6. รัน workflow แล้วดูผล ทำแล้ว

    gh workflow run ci.yml --ref demo/ghas-vulnerable
gh workflow run ci.yml --ref demo/ghas-secure

③ report.html · แถว GitHub Advanced Security ในตารางเทียบ 3 tool (artifact security-report หรือ npm run report)

8. รัน GHAS ในเครื่องได้ไหม

ได้บางส่วน แยกตามส่วนประกอบ:

ส่วนรันในเครื่องวิธี
CodeQLได้CodeQL CLI หรือ VS Code extension "CodeQL" ใช้ query ชุดเดียวกับใน CI License: ใช้ฟรีกับโค้ด open source (repo นี้เป็น public) ถ้าเป็นโค้ด private ขององค์กรต้องมี license GitHub Code Security
Dependency Reviewใกล้เคียงไม่มีเวอร์ชันในเครื่อง ใช้ npm audit --audit-level=high แทนได้ เพราะใช้ฐานข้อมูล GitHub Advisory เดียวกัน (มีใน scripts/local-scan.sh อยู่แล้ว)
Secret scanningไม่ได้ทำงานฝั่ง GitHub เท่านั้น แต่ push protection บล็อกตั้งแต่ตอน git push อยู่แล้ว ถ้าอยากเช็กก่อน commit ให้ใช้เครื่องมือ open source เช่น gitleaks
Dependabotไม่ได้ทำงานบน GitHub เท่านั้น ดู alert ด้วย npm run ghas:alerts

ขั้นตอนรัน CodeQL ในเครื่อง (macOS)

# 1) ติดตั้ง CodeQL CLI (ครั้งเดียว, ~1 GB รวม query pack)
brew install --cask codeql

# 2) สร้างฐานข้อมูลจากโค้ด (JS/TS ไม่ต้อง build)
codeql database create .codeql-db --language=javascript-typescript --source-root . --overwrite

# 3) วิเคราะห์ด้วย query ชุดเดียวกับ CI (security-extended)
codeql database analyze .codeql-db codeql/javascript-queries:codeql-suites/javascript-security-extended.qls \
  --download --format=sarif-latest --output=reports/ghas-codeql.sarif

# 4) ใช้เกณฑ์ gate เดียวกับ CI (fail ถ้า High ขึ้นไป)
node scripts/gate-count.mjs codeql reports/ghas-codeql.sarif
ยังไม่ได้ลองรันคำสั่งชุดนี้ในเครื่องของ POC (ต้องดาวน์โหลด CLI ก่อน) ถ้าต้องการ ผมเพิ่มเป็น npm run ghas:local และใส่ไว้ใน npm run security:local ให้ได้ แล้ว report.html ในเครื่องจะมีแถว GHAS ด้วย ควรเพิ่ม .codeql-db/ ใน .gitignore

9. ข้อดี ข้อจำกัด และสิ่งที่ควรทำต่อ

ข้อดี
  • ฟรีสำหรับ repo public ใช้ action ทางการ ไม่ต้องมี token หรือบัญชีเพิ่ม
  • CodeQL วิเคราะห์ data flow ได้ลึก จับ command injection, SSRF, TLS off ได้แม่น
  • ผลรวมอยู่ใน Security tab ของ GitHub เลย ไม่ต้องเข้า dashboard อื่น
  • SCA ใช้ GitHub Advisory DB รายงาน CVE ได้ละเอียด (29 รายการ)
  • Push protection บล็อก token ที่หลุดตั้งแต่ตอน push
ข้อจำกัด
  • repo private ต้องซื้อ license (คิดต่อ active committer)
  • ไม่มี IaC และ container image scan ต้องใช้ tool อื่นเสริม
  • CodeQL ไม่ fail เอง ต้องเขียน gate เพิ่ม (gate-count.mjs)
  • พลาด path traversal, dangerouslySetInnerHTML, server redirect ในเดโมนี้
  • Secret scanning ไม่จับรหัสผ่านทั่วไป
  • ต้องเปิด Dependency graph เอง ไม่งั้น Dependency Review ใช้ไม่ได้

สิ่งที่แนะนำให้ทำต่อ

  1. เปิด Dependabot alerts และ security updates ที่ Settings → Code security เพื่อให้ได้ fix PR อัตโนมัติบน main
  2. ลอง Copilot Autofix บน alert ของ #9 ใน Security tab แล้วเทียบกับ suggested change ของ Aikido
  3. ถ้าเลือก GHAS: ตั้ง gh variable set GATE_TOOLS --body "ghas" (หรือ "snyk ghas") แล้วทำ CI + Security Gate เป็น required check
  4. เสริม IaC / container ด้วย KICS หรือ Trivy (ฟรี) เพราะ GHAS ไม่มีส่วนนี้
